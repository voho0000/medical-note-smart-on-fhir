# 日期量測優化與重測

2026-09-09。修改限於 `useMedicationEndDateFit`；藥物列資訊、截斷規則與手機／桌面行數不變。

## 修改

- 共用一個 IntersectionObserver、一個 ResizeObserver，以及一組視窗／字型事件監聽。
- 只對與畫面相交的列訂閱尺寸變化並讀取排版。畫面外保留上次結果，捲入後重新確認。
- 每列快取完整文字寬度；改變欄寬只比較剩餘空間，文字、字型屬性或載入字型改變時才重新量測。
- 用同一個動畫影格批次處理，先完成所有排版讀取，再通知 React 更新。
- 清單卸載後解除觀察、事件與待執行工作。快取隨列卸載釋放。

## 千列五組開／關對照

使用與前次相同的密集操作：100／1,000 列、各五組、交替先後順序，共 20 次全部完成。以下是每種模式五次中位數；欄寬是 36 次變動的總耗時，字級是 12 次變動的總耗時。

| 本次 1,000 列 | 關閉量測 | 開啟量測 | 開／關比率 |
| --- | ---: | ---: | ---: |
| 同步掛載 | 1.220 秒 | 2.066 秒 | 1.69× |
| 掛載後三個動畫影格 | 2.917 秒 | 2.594 秒 | 0.89× |
| 連續改變欄寬 | 25.706 秒 | 28.185 秒 | 1.10× |
| 連續改變字級 | 19.779 秒 | 21.128 秒 | 1.07× |
| 緊接字級變化後捲動 | 0.970 秒 | 2.102 秒 | 2.17× |

前次欄寬與字級的開／關比率分別是 2.14×、1.30×；本次為 1.10×、1.07×。這支持量測額外成本減少，但不能把跨次測試的絕對秒數直接相減作為改善百分比：這次連對照組也顯著變慢，機器背景負載較高且有離群值。未刪除任何一輪數據。

同步掛載的額外耗時仍在，不能宣稱初次載入全面改善。一次掛載千個完整藥物列的整體排版負擔也仍存在，本次沒有把清單改成虛擬捲動。

## 捲動尖峰的補充驗證

混合操作測試中，開啟組五次有三次捲動約 2.1–2.3 秒，另外兩次約 1.03 秒。原因未確定，不能直接歸因於垃圾回收或前一階段排版。

為區分獨立捲動與混合操作，另外完成五組千列對照：掛載後等待三個影格、500 ms 與另外三個影格，再做 24 次相同捲動，不先改欄寬或字級。

| 獨立捲動 | 關閉量測 | 開啟量測 |
| --- | ---: | ---: |
| 五次總耗時中位數 | 0.950 秒 | 0.917 秒 |
| 十次測試各組最長長任務的最大值 | 83 ms | 82 ms |

獨立捲動沒有重現秒級停頓，也未觀察到總耗時明顯退步；此結果不能排除真實使用時的混合操作尖峰。兩組皆仍有超過 50 ms 的影格，並非每個影格都流暢。

## 正確性驗證

- 17 個相關測試套件：155 項通過；再增加字型載入／畫面外快取失效案例後，日期量測套件 8 項通過（相關案例合計 156 項）。
- 測試直接驗證千列只建立一組觀察器、不可見列不量測，以及縮窄／放寬沿用快取、文字與字型變更、捲出再捲入、必要日期保留、卸載清理與無 IntersectionObserver 的降級行為。
- 修改檔案的 ESLint 與 hook 獨立 TypeScript 檢查通過。
- 隔離測試頁正式版建置通過。完整應用建置仍因其他套件缺少匯出失敗，例如 `@voho0000/clinical-lab-normalization/canonical`；未改動相依套件。
- 真實 Chrome 檢查 320、390、430、768、1024、1440 CSS px，以及根字級 16／32 px。無頁面水平溢出；放大時收起結束日、加寬或縮小字級時恢復、新捲入列與清單重開均正常。極窄螢幕配合雙倍字級仍有既有的大量省略，本次未重新分配欄位。

全部使用合成資料與實際 MedicationItem，不含 FHIR 下載、解析、分組或完整病人工作區的端到端效能。
