## Part A — 安全性細節

### S1（HIGH）登出不清 SMART token
`signOut`（`src/application/providers/auth.provider.tsx:297-330`）清了 AI keys、session crypto key、匯入 bundle、AI 快取，但 fhirclient 的 `SMART_KEY` 指標與 token JSON（sessionStorage，`fhir-client.service.ts:55-62` 讀取）原封不動，`FhirClientService.clearClient()` 也沒被呼叫。共用工作站按登出後，分頁仍能以有效 token 繼續打 FHIR server 直到 token 過期。修法：signOut 內移除 `SMART_KEY` 與其指向的 entry、呼叫 `clearClient()`、導離病歷頁。

### S2（MEDIUM）Resend key 在 `.env.local`
`RESEND_API_KEY=re_...`。未進 git（已驗 `git ls-files` 與 `git log -S`），但 repo 在 `My Drive/` 下持續同步到個人 Google Drive。唯一消費者是 dev/Vercel 專用 `app/api/feedback/route.ts:215`。修法：輪替該 key，只放 Functions/Vercel secret store，從 `.env.local` 刪除。

### S3（MEDIUM）on-prem artifact 掃描範圍不足
`scripts/audit-onprem-artifact.mjs:5` 與 `scripts/sanitize-onprem-artifact.mjs:5` 都 root 在 `out/_next/static`，但 `scripts/package-onprem.mjs:48-54` tar 整個 `out/`。route HTML（含 inline bootstrap/RSC payload）、`public/` 複本、demo bundle 都不在 forbidden-domain 掃描範圍。修法：兩支 script 改 root 到 `out/`（沿用副檔名過濾）。

### S4（治理）Firestore 聊天持久化含真病人 PHI
`chat-session.repository.ts:48-94` 存完整訊息文字、`patientId`、`fhirServerUrl`、`replyTo.excerpt`（病歷原文摘句）；`useChatHistoryDrawer.ts:24` 預設 `persistenceEnabled ?? true`，SMART 真病人 session 也自動存。使用者訊息未 scrub（scrub 只做在 outbound-to-AI，設計如此），貼上的姓名/病歷號會落地 Firestore。SECURITY.md 已列為 residual risk——這是治理行動項而非未知漏洞。短解一行：對 real-SMART-issuer session 停用 auto-save（自訂 endpoint 已有相同前例）；或加 TTL＋機構帳號政策後再上真 PHI。

### S5（部署）CSP／headers 現況
- `app/layout.tsx:27-40` meta CSP（production only）：`script-src 'self' 'unsafe-inline'`、`connect-src 'self' https: wss:`（任意 HTTPS 主機）、`img-src … https:`。
- `next.config.ts:140-160` 的 headers（`frame-ancestors` allowlist 等）在 GH Pages／mediprisma 靜態鏡像不會送出（程式註解自己有寫）；`frame-ancestors` 無法用 meta 傳遞 → github.io 版無任何 framing 限制。
- 意涵：任一 HTML injection 立足點可升級為任意 script 執行並外送 PHI 到任意 HTTPS 主機。理由（static export inline scripts、任意 SMART iss）已記錄於 SECURITY.md；可行的殘餘行動：mediprisma.tw 補真實 response headers、考慮 script hashes。
- on-prem `deploy/intranet/Caddyfile.example` 很嚴，但 `script-src 'self'` 會擋 Next inline bootstrap——採用者可能私加 `unsafe-inline`；建議預算 hash 寫進範例。

### S6（LOW-MED）narrative 遠端圖片
`sanitize-narrative.ts:95-105` 只在 `DEPLOYMENT_CONFIG.isOnPrem` 剝除非同源 `<img>`；cloud 版照載（CSP `img-src https:` 放行）。Markdown/AI 輸出已正確擋圖（`MarkdownRenderer.tsx:49-53`）。修法：cloud 也剝除或 click-to-load。

### S7（LOW）npm audit
prod deps 4 high：`nanoid <3.3.18`（DoS，需 size-0 custom generator，無現實攻擊路徑）、`postcss`/`sharp`/`next`（static export 下皆 build-time）。方便時 `npm audit fix`。DOMPurify 已鎖 3.4.12（舊 audit A2 已解）。

### S8（驗證良好——不要重工）
- outbound PII scrub 真實存在且接得廣：`pii-text-scrub.ts` 用於 clinical context（`use-clinical-context.hook.ts:247`）、agent chat 三處、每個 FHIR tool 回應（`fhir-tools.ts:561`）、全部 summary/safety/insights/report/followup/title use-cases。
- iss allowlist + PKCE required + public client（`smart-issuer-policy.ts`、`app/smart/launch/page.tsx:79-89`）；on-prem fail-closed。
- XSS 面：所有 `dangerouslySetInnerHTML` 過 DOMPurify；react-markdown 無 rehype-raw；連結 `noopener noreferrer`；無 eval/new Function；`window.open` 有 opener 防護；IPS 列印路徑有 escape。
- 兩個 postMessage handler（medcloud、nhi-viewer）都驗 source+origin+schema。
- 無 analytics 呼叫；feedback 表單不收 patientId；URL 無 PHI；repo 內只有 genuinely-public 設定值。
- 本地 bundle AES-GCM + tab-scoped key + 12h TTL；登出清 AI 快取與 keys（除了 S1 的 SMART token 缺口）。

### 量測基準（out/ @ Aug 13）
