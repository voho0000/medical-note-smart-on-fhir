## 第一部分　第一次會議建議議程（副院長層級必決，共 7 題）

第一次會議的目標不是討論產品細節，而是把**範圍、組織、原則、pilot、依賴**五件事定下來，後面分組才動得了。

### A1　小組任務範圍：再造什麼、不再造什麼

- **為何要議決**：「門診系統再造」字面可大可小。最近討論聚焦在「診前資料收集 → 診前摘要 → 診中 AI 輔助 → 資料回存中台」四段；但掛號、報到、候診叫號、批價等傳統門診流程也可能被期待。範圍不定，資訊室與臨床各自想像不同。
- **選項**：
  1. 窄：只做診前資料與診中資訊呈現（醫析為主體）。
  2. 中：加上與掛號／報到／通知的介面（需資訊室共同負責）。
  3. 寬：整體門診流程再造，含動線與人力配置。
- **建議決議**：本期範圍採**選項 2**。以「病人在看診前把該說的說完、醫師在看診時把該看的看到」為目標；掛號／報到／通知系統只做**介面**不改造。動線與人力配置列為下一期。
- **決策層級**：副院長。**需邀請**：資訊室主管、門診部主管。

### A2　小組組成、分工與決策方式

- **為何要議決**：目前所有需求都出自兩位醫師的對話，還沒有護理、資訊、病歷、個資、研究倫理的正式代表；許多待決事項（見第二部分）的決策者根本不在現有討論裡。
- **建議決議**：
  - 召集人：副院長。執行秘書：醫學人工智慧發展中心。
  - 臨床組：首發 pilot 科代表（擔任 PI）＋ 第二批科別代表。
  - 護理組：門診護理長或個管師代表（負責發邀請、現場協助、待辦接手的流程主人）。
  - 資訊組：資訊室（launcher 參數、預約通知、對外入口、中台介面）。
  - 治理組：病歷室、個資保護／資安、研究倫理（IRB）窗口。
  - 決策方式：小組決議 → 副院長核定；技術選型授權執行秘書，政策性與跨單位事項回小組。
  - 頻率：前三個月每兩週一次，之後每月一次。
- **決策層級**：副院長。

### A3　與院內既有專案的關係與定位

- **為何要議決**：已知重疊點有三：華碩正在做住院 patient summary 與「診前提問」；眼科已有病人端 LLM 對話（數位分身）並走過法規／IRB 路徑；資訊室的醫析 launcher 已在門診使用。不先講清楚，會重工或互相踩線。
- **建議決議**：
  - 醫析定位為**出題端**（依科別、初複診、雲端資料決定問什麼）與**閱讀端**（答案進醫師診前摘要並供 CDSS 使用）。填寫介面與表單引擎不自建，可接任何工具。
  - 請執行秘書於下次會前與華碩專案窗口確認「診前提問」內容與範圍，回報小組。
  - 病人端對話功能的法規與 IRB 路徑，沿用眼科先例，邀眼科團隊分享一次。
  - 各科需求表單同時收「門診」與「住院」兩欄，供住院 summary 專案共用，但輸出是兩個產品。
- **決策層級**：副院長。**需邀請**：華碩專案窗口、眼科團隊。

### A4　病人自填資料（PHI）的儲存政策

- **為何要議決**：這是所有後續功能的前提。醫析現行政策是「server 端不存任何病人 FHIR 資料」，但診前問卷天生要跨裝置、跨時間持久保存，且是病人自填的個資。不開例外就做不了；開例外要決定存哪裡、存多久、誰負責。
- **選項**：
  1. 院內網儲存服務（本中心自架小型 FHIR store）：不出院、不依賴資訊室；但居家填寫到不了。
  2. 雲端（醫析既有 Firebase）：居家可用、實作快；PHI 上雲，需個資同意與院方核准。
  3. 院方對外入口或 DMZ 轉送進院內：居家可用且不留雲端；需資訊室開通。
- **建議決議**：Phase 0 採**選項 1**；Phase 1 居家填寫在 2 與 3 之間由資訊室與個資單位評估後回小組決定。無論哪個，先修訂資料保存政策文件，明列「診前問卷」為例外、保存期限、稽核方式。
- **決策層級**：副院長核定；個資／資安單位審。

### A5　病人端 AI 的法規與倫理定位

- **為何要議決**：衛福部 2026-05-29 指引把「AI Agent System」排除在外；病人端對話式問診比表單更接近那條線。若不先定位，pilot 申請書與 IRB 都會卡。
- **建議決議**：小組正式採用以下定位，寫進所有申請文件：
  - **受限任務**：只收資料與釐清，不做診斷、分流、用藥建議。
  - **無自主行動**：不寫回醫院病歷；答案由病人逐題確認；醫師覆核後才使用。
  - **驗證量表不由 AI 改寫**：KCCQ、STOP-BANG 等題幹與計分固定，AI 只決定要不要填、何時填。
  - **急性訊號升級**（胸痛、自殺意念）是確定性規則的流程提醒，非臨床判斷。
  - 主張非醫療器材；等效性研究走 IRB。
- **決策層級**：副院長；研究倫理窗口確認措辭。

### A6　首發 pilot 科別、診別與成功指標

- **為何要議決**：要有一個科先跑通，其他科才有範本。心臟內科已有 PI 與具體需求（心衰 KCCQ、高血壓 STOP-BANG、本科上次檢查摘要）。
- **建議決議**：
  - 首發 pilot：建議**心臟內科**（已有具體需求與 PROM 構想），由該科指派 PI；心衰特別門診或一般心臟科擇一，由 PI 決定。
  - 第二批候選：腎臟科、新陳代謝科、家醫科（各科需求初稿已有骨架）。
  - Pilot 主要指標採**「醫師診中開啟並閱讀問卷／摘要的比例」**，不採填答率；次要指標：填答完成率、填答時間（通用核心 ≤ 3 分鐘）、問卷新發現且雲端沒有的過敏／懷孕比例、「來門診沒看到之前檢查」零發生。
- **決策層級**：小組決議，副院長核定。

### A7　對資訊室的依賴清單與承諾時程

- **為何要議決**：Phase 0 設計成資訊室依賴為零，但 Phase 1 之後每一步都要資訊室配合。清單要在第一次會就攤開，讓資訊室排資源，而不是每次會議才冒出一項。
- **建議決議**：請資訊室就下列項目回覆可行性與時程：
  1. 醫析 launcher 新增科別參數（`dept=`），碼表採健保科別碼或院內科別碼擇一。
  2. 預約通知（簡訊／App）能否夾帶院方簽發的診前填寫連結或 QR code。
  3. 對外入口或 DMZ 收件路徑（對應 A4 選項 3）。
  4. 病人識別命名空間、預約與報到事件介面。
  5. 人事室科別資料表供醫師科別預設值。
  6. 資訊中台接受問卷資料的介面規格與時程（Phase 3）。
- **決策層級**：資訊室主管承諾，副院長裁示優先序。

## 第四部分　第一次會議建議流程（90 分鐘）

1. 副院長說明成立緣由與期待（10 分）。
2. 執行秘書簡報：現況、四份需求草稿摘要、重疊專案（15 分）。
3. 心臟內科說明臨床痛點與 pilot 構想（10 分）。
4. 逐題議決 A1–A7（45 分）。
5. 指派 B 表各題負責人與回報期限；訂第二次會議日期（10 分）。

**會後決議文件建議格式**：每條決議寫「決議事項／負責單位／完成期限／下次回報內容」，並把 A4 與 A5 兩條原則性決議另抄送個資保護與研究倫理單位備查。
